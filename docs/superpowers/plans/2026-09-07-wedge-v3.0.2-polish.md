> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v3.0.2 — empty menu-bar SF Symbol refresh (`leaf`) and restore native filled `List` selection in the panel.

**Architecture:** Two one-file tweaks. Status item empty state swaps the SF Symbol name. Panel drops the plain/hidden-background combo that kills system selection so AppKit draws the fill again. Docs note the patch tag.

**Tech Stack:** AppKit `NSStatusItem` + SF Symbols; SwiftUI `List(selection:)` on macOS.

**Spec:** [docs/superpowers/specs/2026-09-07-wedge-v3.0.2-polish-design.md](../specs/2026-09-07-wedge-v3.0.2-polish-design.md)

## Global Constraints

- Empty bar stays **icon only**; non-empty stays **title only** (no circle beside title).
- SF Symbol only — no custom Assets icon.
- System selection fill only — no custom `listRowBackground` selection paint.
- Borders: opportunistic only (side effect of native list fix).
- No v4 / cloud / Dock / confetti.
- Ponytail: fewest files; no new abstractions; trivial symbol swap needs no unit test — human smoke is the check.
- Product language: **one thing** · **Up next** · **Done**.

### Task 2: Restore native list selection fill

**Files:**
- Modify: `wedge/Views/PopoverContentView.swift` (`list` computed property)
- Test: none (visual smoke)

**Interfaces:**
- Consumes: existing `List(selection: $selection)` + ↑/↓/⌫ behavior
- Produces: same selection binding; visible system filled highlight on selected rows

- [ ] **Step 1: Stop hiding the list’s native chrome**

Current list modifiers (approx.):

```swift
.listStyle(.plain)
.scrollContentBackground(.hidden)
.frame(maxHeight: .infinity)
.onDeleteCommand { deleteSelectedItem() }
```

**First try (ponytail — delete, don’t paint):**

1. Remove `.scrollContentBackground(.hidden)`.
2. Change `.listStyle(.plain)` → `.listStyle(.inset)`.

Keep `List(selection: $selection)`, tags, `onMove` / `onDelete`, insets, and keyboard delete as they are.

```swift
List(selection: $selection) {
    ForEach(store.items) { item in
        itemRow(item)
            .tag(item.id)
            .listRowInsets(EdgeInsets(top: 8, leading: 6, bottom: 8, trailing: 6))
    }
    .onMove { indices, newOffset in
        store.move(from: indices, to: newOffset)
        onChange()
    }
    .onDelete { indexSet in
        let ids = indexSet.map { store.items[$0].id }
        ids.forEach { store.delete(id: $0) }
        if let editingItemID, ids.contains(editingItemID) {
            self.editingItemID = nil
        }
        if let selection, ids.contains(selection) {
            self.selection = nil
        }
        onChange()
    }
}
.listStyle(.inset)
.frame(maxHeight: .infinity)
.onDeleteCommand { deleteSelectedItem() }
```

Do **not** add custom `listRowBackground` for selection.

- [ ] **Step 2: Smoke selection + panel feel**

Run the `wedge` scheme with 2+ items:

1. Open panel; click a row (not into edit) or use ↑/↓ → selected row shows a **filled** highlight (system accent/secondary), not outline-only / invisible.
2. ⌫ still deletes the selected row when not editing.
3. Tap text still enters inline edit; Return commits.
4. Drag grip / reorder still works.
5. If inset looks too “boxed,” try `.listStyle(.automatic)` or `.sidebar` **without** re-adding `.scrollContentBackground(.hidden)`. Prefer whatever restores fill with the least chrome.
6. Accept softer separators only if they come free — no separate border project.
